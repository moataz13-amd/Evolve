# ربط EVOLVE بـSupabase والنشر على Vercel

الكود يدعم الربط بمشروع Supabase من ملفات البيئة. لوحة الإدارة على `/admin` لا تحتوي حسابًا تجريبيًا أو صلاحيات وهمية.

## 1. إعداد المشروع

أنشئ مشروع Supabase جديدًا. من إعدادات المشروع انسخ Project URL ومفتاح publishable أو anon العام. ملف `frontend/.env` موجود بالفعل؛ أضف القيم إليه:

```env
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_ANON_KEY
VITE_DEMO_MODE=false
```

الفرونت يستخدم الرابط مع `VITE_SUPABASE_ANON_KEY` فقط. لو تحتاج service role key، ضعه باسم `SUPABASE_SERVICE_ROLE_KEY` في `backend/.env` فقط. هذا المتغير مجهز للعمليات الخاصة بالسيرفر، ولا تستخدمه الواجهة أو أوامر migrations الحالية. لا تستخدم service role أو secret key في أي متغير يبدأ بـ`VITE_` لأن هذه المتغيرات تصل إلى المتصفح وتتجاوز تلك المفاتيح RLS. أعد تشغيل Vite بعد تغيير الملف.

## 2. قاعدة البيانات والصور

لو ظهر الخطأ `relation "admin_profiles" already exists`، فالجداول موجودة بالفعل. لا تشغّل `setup.sql` على المشروع القائم. لتطبيق تحديثات مواعيد التوصيل ومفاتيح إظهار نصوص الهيرو، شغّل محتوى `backend/supabase/updates.sql` من SQL Editor. يمكن تكراره بدون إعادة إنشاء الجداول أو حذف البيانات أو استبدال الإعدادات المحفوظة. Cloudinary لا يحتاج أي SQL جديد؛ نشر وظيفة الصور موضح في [دليل Cloudinary](CLOUDINARY_SETUP_AR.md).

نفّذ ملفات `backend/supabase/migrations/*.sql` بالترتيب الرقمي، كل ملف مرة واحدة، من SQL Editor في مشروع جديد. الملفات تنشئ الجداول والعلاقات والفهارس وRLS ودوال الطلبات والمخزون، وbucket الصور `evolve-media` وسياساته.

للمشروع الجديد يمكنك بدلًا منها تشغيل `backend/supabase/setup.sql` مرة واحدة. الإعداد يشمل الآن أقسام الهوم والنصوص والصور وFAQ افتراضيًا؛ لا ينشئ منتجات أو مخزونًا للبيع. migration رقم `011_initial_homepage` يضيف هذا المحتوى فقط عند غياب أقسام الهوم، ويحافظ على المحتوى المعدّل. لو طبّقت ملفات 001–010 سابقًا، شغّل 011 فقط أو استخدم `npm run db:homepage:restore --workspace backend` عند توفر service role في بيئة الباك إند. لا تعيد تشغيل setup على مشروع سبق إعداده.

Supabase CLI مثبت ضمن backend. ضع Project Ref في backend/.env (وكلمة مرور الداتابيز عند الحاجة)، ثم من جذر المشروع:

```sh
npx supabase login
npm run db:link
npm run db:push
```

ملف `backend/supabase/seed.sql` اختياري للتطوير: يضيف محتوى الصفحة الرئيسية وأقسام EVOLVE ومنتجات بمقاسات وألوان وSKU ومخزون توضيحي. المنتجات تبدأ كمسودات. لا ينشئ مستخدمين أو مديرين أو طلبات أو تقييمات وهمية. يمكن تشغيله أكثر من مرة؛ راجع البيانات والصور والمخزون قبل نشر أي منتج. لا تنفذه على قاعدة قائمة تحتوي بيانات مختلفة بنفس slugs دون مراجعة التعارضات.

الـbucket عام للصور التسويقية والمنتجات، وليس لحفظ ملفات خاصة. لا يمكن حذف سجل صورة مرتبطة بمنتج أو محتوى بسبب العلاقات في قاعدة البيانات. إذا فشل تنظيف Storage بعد حذف سجل غير مستخدم، تظهر رسالة واضحة ويمكن للمدير تنظيف الملف من Supabase.

## 3. أول مدير

أنشئ مستخدم الفريق من صفحة Authentication في Supabase، وسجّل UUID الخاص به. ثم نفّذ من SQL Editor، بعد استبدال UUID والاسم:

```sql
insert into public.admin_profiles(id, name, role, active)
values ('REPLACE_WITH_AUTH_USER_UUID', 'Store owner', 'super_admin', true);
```

سجّل الدخول من `/admin/login`. التسجيل العام في `/account` ينشئ حساب عميل فقط؛ لا يمنح أي دور إداري.

| الدور         | الصلاحيات                                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------------------------- |
| `super_admin` | إدارة المتجر والإعدادات والفريق وكل العمليات                                                                  |
| `admin`       | المنتجات والمخزون والطلبات والعملاء والمحتوى والعروض والصور                                                   |
| `editor`      | تعديل الكتالوج والمحتوى والصور؛ قراءة المخزون؛ لا تعديل للكميات أو التكاليف أو الطلبات أو العملاء أو حذف دائم |

لإضافة عضو لاحقًا، أنشئ حسابه في Supabase ثم أضف UUID من صفحة Team. لا يمكن تعطيل آخر super admin. صلاحيات الواجهة ليست الحماية الوحيدة؛ قاعدة البيانات تفرضها أيضًا.

## 4. إدارة المحتوى والبيع

من Homepage افتح Edit content. يمكنك تعديل النص العربي والإنجليزي والصورة ورابط الزر وترتيب المحتوى. Publish وActive يتحكمان في ظهور القسم. صفوف الأقسام والفوائد تصنع الكروت. Featured products يقبل اختيارًا يدويًا حتى 24 منتجًا، أو مجموعة تلقائية عند إفراغ الاختيار اليدوي.

أضف المنتج والصور والـvariants ثم فعّل Active. السعر البديل والمخزون يتبعان اللون والمقاس. تغيير الكمية ينشئ سجل حركة؛ المخزون لا يُعدّل مباشرة من المتصفح. نسخ المنتج يصنع مسودة بمخزون صفر وSKU جديد. المنتجات المرتبطة بطلب أو حركة مخزون لا تُحذف؛ استخدم الأرشفة.

من Settings اضبط العملة والشحن والحد المطلوب للشحن المجاني وبيانات المتجر وروابط التواصل وSEO. غيّر العملة قبل بدء استقبال الطلبات، لأن تقارير الإيراد تفترض عملة متجر واحدة. `Allow checkout` مغلق افتراضيًا.

عند تفعيل checkout، يجب على العميل تسجيل الدخول. قاعدة البيانات تتحقق من المنتج والـvariant والتوفر والكميات والكوبون، وتحسب الأسعار والشحن والخصم، ثم تنشئ الطلب وتخصم المخزون في معاملة واحدة. إعادة المحاولة بنفس مفتاح الطلب لا تنشئ طلبًا جديدًا. إلغاء الطلب قبل شحنه يعيد المخزون مرة واحدة؛ الطلب المشحون يحتاج معالجة إرجاع خارج مسار الإلغاء.

**لا توجد بوابة دفع في هذه النسخة.** الطلب يُسجل بحالة Payment pending ولا تُجمع بيانات بطاقة. تغيير حالة الدفع من الإدارة يسجل عملية مالية مؤكدة خارج الموقع؛ لا ينفذ تحصيلًا أو استردادًا ماليًا. نموذج التواصل الحالي معاينة ولا يرسل بريدًا. اشتراك newsletter يُحفظ، لكن حملات البريد لا تُرسل تلقائيًا. السياسات التجارية والمقاسات والصور النهائية تحتاج بيانات البراند قبل الإطلاق.

## 5. إعداد Auth والنشر

في إعدادات Authentication ضع Site URL على رابط المتجر النهائي، وأضف رابط `/account` للدومين النهائي وlocalhost إلى Redirect URLs المسموحة. اضبط تأكيد البريد وSMTP الخاص بك لتوصيل رسائل حسابات العملاء والفريق.

في Vercel اجعل Root Directory جذر المشروع، واختر Vite، وBuild Command هو `npm run build`، وOutput Directory هو `frontend/dist`. أضف متغيري Supabase العامين و`VITE_DEMO_MODE=false` ثم انشر. ملف `vercel.json` يعالج روابط React Router المباشرة مثل `/admin/products`، ويضيف رؤوس حماية أساسية. أي تغيير لمتغيرات Vite يحتاج إعادة build/deploy.

وضع المنتجات والطلبات المحلية التجريبي يعمل أثناء `npm run dev` فقط عند غياب بيانات Supabase، ما لم تُعطّل `VITE_DEMO_MODE`. نسخة الإنتاج بدون إعداد Supabase تعرض عدم توفر الاتصال ولا تعرض بيانات بيع تجريبية.

## 6. التحقق بعد الربط

```sh
npm install
npm run check
npm run dev
```

الفحوص المحلية تشمل التنسيق وESLint وTypeScript والبناء واختبارات المتجر، واختبار PostgreSQL باستخدام PGlite لجميع migrations، مع حالات للصلاحيات وعزل العملاء وحساب الأسعار والمخزون والإلغاء والـseed. الاختبار المحلي يحاكي جداول Auth وStorage، ولا يحل محل التحقق الفعلي من Supabase Auth والبريد ورفع الصور على المشروع المتصل.

بعد الربط جرّب الأدوار الثلاثة، رفع صورة وتعيينها وحذف صورة غير مستخدمة، تغيير سعر منتج ومخزونه ومحتوى الهيرو وFAQ، إنشاء طلب عميل، ثم تأكد من ظهوره في الإدارة ومن خصم المخزون. جرّب الدخول المباشر لصفحة إدارة من حساب عميل ومن عضو editor، واختبر روابط الصفحات بعد refresh على Vercel. لا تعتبر الاتصال أو النشر أو الدفع مختبرًا قبل تنفيذ هذه الخطوات على المشروع الفعلي.
